# StuHelper Moderation

内容审核模块，提供按学校的审核策略、举报、作者修改与删除申请、审核决定和失败重试。内容模块保存正文并执行决定，moderation 通过公开 Content 接口协作。

发布检查支持直接公开、待审核和公开后检查，评课与回复默认直接公开，资料默认待审核。读取检查不产生任务，内容事务的 outbox 在提交后创建审核任务。处理中同一用户对同一对象的同类申请合并证据。

审核决定检查管理员当前学校权限与内容修订。后台在事务外调用内容模块，决定 ID 保持不变；超时后重试原决定。旧修订、无权限与内容不存在转入明确失败状态，不覆盖新内容。

管理端可查看待审原文、处理举报和作者申请，支持隐藏、恢复、修改正文和讨论身份。审核规则接口分别返回学校配置和实际生效规则。管理界面区分决定已保存、已执行和投递失败，未知结果重试沿用原请求。

作者可以对已有决定提出复核，复核必须由另一名具备复核权限的管理员处理。内容作者可查看决定并申请复核，其他举报者的私密证据不向作者公开。

队列支持内容类型、申请类型、时间、学校、状态和对象筛选，同一内容的处理记录集中查看。批量处置先预览，最多 20 项，分别返回决定已保存或拒绝的结果。每项保持原幂等标识，重复请求不会增加业务效果。

优质认定、撤销认定和评价归属更正通过同一决定流程执行。内容模块再次核对权限、来源及修订后保存业务变化。通知、奖励和外部订阅由对应能力消费业务事件。

候选接口为 0.4.0，申请类型包括 appeal，决定动作包括 feature、unfeature 和 reassign。客户端按 OpenAPI 生成接口。

新建举报使用当前内容准入。本人待审核举报可继续补充证据，即使资格失效或事实服务不可用；补证只更新本人记录，不读取目标正文。已作决定的举报拒绝追加，结案后再次举报重新检查准入。

## 使用与检查

```sh
make setup
bash scripts/check-with-postgres.sh
```

先维护 `contracts/moderation.openapi.json`，再执行 `make generate`。迁移与运行身份分离，运行身份只访问 moderation schema。所有 HTTP 入口均需认证，管理列表、决定、策略和重试执行学校范围授权。

每次处理最多 50 个任务，外部决定调用最长 10 秒。租约防止重复领取，失败按 5 秒至 1 小时退避，决定超过 24 小时仍失败则等待管理员处理。不可用故障可按任务修订重新排队。

PostgreSQL 测试覆盖举报合并、作者请求限制、策略幂等、学校范围、超时重试、旧决定拒绝与私密字段投影。对外结果隐藏操作账号和修改正文，实际正文通过内容模块当前权限读取。

当前支持课程评价、导师评论、回复和资料的任务类型及策略。资料正文、文件和访问权益由 resources 保存，审核服务只保存任务与决定。资料只接受发布、隐藏、恢复、删除和驳回操作。真实管理员身份与生产运行验收分别进行。

复核请求契约包含 appeal 与 previous_task_id，生成客户端保留原任务标识。服务端仍校验内容作者、原决定和不同复核人。

资料侵权投诉由 resources 完成登录、材料和目标校验，经 SubmitResourceComplaint 登记。该模块接口不对 HTTP 开放，以相同幂等键和载荷恢复未确认请求。通用举报入口继续要求内容准入，投诉回执不含目标正文。

举报及投诉按账号限制每分钟 10 次新提交，同键重试保留原结果，超限返回 429 且不改变任务。限制与任务写入在同一数据库事务执行，失败不消耗次数。

审核决定和终态结果按[事件契约](contracts/events.md)写入事务 outbox，并在提交后通知 moderation_outbox。relay 通过公开 Go OutboxReader 读取与确认事件，单批最多 100，并可排除最多 1000 个暂缓投递的主题。backend 的 LISTEN、消费者 inbox 与重试装配由后续任务接入。

受信管理适配器可通过 Repository.ReadAudit 查询[脱敏审计](contracts/audit.md)。查询支持范围先过滤、最多 101 条、事务可见性快照与排他游标。现有审计表需按最终结构建立，本轮不转换历史数据。

## 反馈收件箱（2026-11-15）

feedback 包保存全站邮箱来信、附件引用、状态、处理人、内部备注和回复记录。backend 接入私有邮箱、平台存储与当前会话，公共模块不保存邮箱密码。管理接口位于 /api/v1/moderation/feedback，OpenAPI 与生成 SDK 同步维护。

读取、处理和回复分别要求 moderation.feedback.read、moderation.feedback.manage、moderation.feedback.reply。授权范围为全站及 moderation 模块，单校授权不能读取全站来信。列表、详情、附件和操作均检查当前权限，并写入不含邮件正文、地址和附件内容的审计。

状态为 new、processing、resolved、spam。保存使用修订号和幂等键，冲突不覆盖已有处理。SMTP 回复先保存发送记录，确认接受后记为 sent；失败和未知结果分别保存，同键重试不会再次发送未知邮件。

每封原始邮件最多 12 MiB，正文最多 200000 字节，附件最多十个、每个最多 5 MiB。原始邮件总预算 2 GiB，活动记录最多十万，清理摘要最多一百万。达到上限暂停接收并保留服务器邮件。清理材料释放活动容量，摘要达到上限时由运维评估后续归档方案。

每个发件人每小时最多二十封完整来信。超过限频的来信只保存摘要元数据，标记垃圾和可疑，省略正文及附件。入库按 Message-ID、发件人和内容摘要去重，UIDVALIDITY 与 UID 游标由同模块持久保存。

结案后保存十二个自然月，每轮最多清理五十条，先删除存储对象再删除记录和幂等结果。重新打开的案件停止清理。只保留无原文的摘要标记以防旧邮件再次导入。审计按十二个月、每次一百条清理，专用数据库函数只允许清理反馈审计，运行身份没有普通审计删除权限。

真实 PostgreSQL 测试覆盖并发去重、修订冲突、即时拒绝、审计脱敏、限频、容量、未知回复及到期清理。IMAP、SMTP 与浏览器组合由 backend 和 Admin 验证。真实邮箱及生产验收记录于私有 ops 交接。
